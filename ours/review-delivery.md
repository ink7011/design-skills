# 评审交付模式：评审页 / 文档中心 / 一键启动器

> 沉淀自真实实践的通用交付模式，与任何具体项目无关。
> 让任何人（包括非设计师）双击一个文件就能看到全部设计与决策。

## 三件套

### 1. 评审页（每轮迭代的标配产物）

静态 HTML，包含：

- **决策依据**：为什么是这个方向（引用规则表/调研结论）
- **修订历史**：Rev A/B/C/D...每条注明改了什么、为什么改——这是评审时最有信息量的部分
- **差异逻辑表**：每个档位/变体一句"说得出"的设计语言
- 全部资产网格展示（深浅成对）
- 技术要点（裁切方式/渐变坐标/字体栈）

关键细节：所有 `<img src>` 加 `?v=xxx` 版本参数，防止浏览器缓存上一轮旧图——
评审看到旧图是高频事故。

### 2. 文档中心（index.html）

列出所有轮次评审页、规范文档、资产的入口。
评审页有轮次、规范会演进，但入口永远只有一个。

### 3. 一键启动器（.command / .sh）

macOS 双击即用：

```bash
#!/bin/bash
cd "$(dirname "$0")"
PORT=8742
URL="http://localhost:$PORT/docs/index.html"
if ! curl -s -o /dev/null --max-time 1 "$URL"; then
  nohup python3 -m http.server $PORT >/tmp/my-server.log 2>&1 &
  sleep 1
fi
open "$URL"
```

要点：幂等（服务在跑就直接开页面）、相对路径（跟着包走）、服务根目录起在**包根**
（评审页图片用 `/outputs/...` 绝对路径时不会 404）。

## 为什么这套东西有效

- 评审成本降到"双击"：不需要本地起服务知识、不需要知道文件路径
- 修订历史让"为什么改成这样"永远可答——比口头解释可靠
- 版本参数消除了"我改了但你看到的还是旧的"这类信任损耗

## 演进方向

- 评审页从静态 HTML → 生成脚本（资产清单 json → 页面），避免手工维护图片列表
- 启动器可以加"打开最新一轮评审页"的语义（读一个 `latest` 文件）
