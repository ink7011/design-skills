# HTML 对抗性审查方法论（Builder / Reviewer 分离）

> 来自真实门户项目的实战沉淀：构建与审查分离、八类已知失败模式、
> 可自动化的验证技术要点。构建侧工艺见 [html-web-design.md](html-web-design.md)，
> 截图验收习惯见 [visual-qa-loop.md](visual-qa-loop.md)，本文是"审查侧"的完整体系。

## 1. 为什么 Builder / Reviewer 要分离

写代码的 agent 有"维护自己作品"的动机：它倾向于确认自己刚写的部分能工作。
审查 agent **没有参与编写**，唯一目标是找到问题——这是两个不同的任务，
应该由两个独立上下文执行，而不是同一个 agent 自查。

三条纪律：

1. **只读**：审查者绝不修改被审项目文件，只读取与运行只读命令。
2. **证据**：每条发现必须给出位置（file:line 或页面位置）与可复现证据
   （代码片段 / 截图观察 / 交互路径），不接受"我觉得"。
3. **否定偏好**：宁可误报不漏报；对"看起来能用"的实现追问边缘情况。
   最终裁决以可复现证据为准。

## 2. 审查维度清单

**A. 语义与结构**：地标完整；标题层级不跳级；ARIA 承诺的键盘行为真的实现
（menu/listbox/tab 必须可方向键操作）；表单 label 显式关联；图标按钮有 aria-label。

**B. 响应式**：逐断点检查（手机逻辑分辨率 / 640 / 900 / 1080 / 1440）；
半宽字段小屏挤压；绝对定位碰撞区间；sticky 层叠；横向溢出。

**C. 视觉与排版**：对比度（正文 ≥ 4.5:1）；字号层级；间距节奏；
动效克制；`prefers-reduced-motion` 降级。

**D. CTA 漏斗审计**：列出**所有**可点击入口及最终去向；两个入口导向同一终点的，
标记为重复 CTA 并评估必要性（受众是否不同？）；死链与空终点；
表单必填标记与实际校验一致，提交后有状态闭环。

**E. 客户模拟（三角色走查）**：以第一人称走完整路径——
买家（能不能快速找到候选）、申请者（从理解到提交有几步、哪里疑虑）、
高管（30 秒扫一眼是否讲清"是什么/凭啥信/下一步"）。

**F. 品牌与保密红线**：LOGO 无变形/动画/重绘；自维护一份保密词表
（客户名、分成比例、谈判状态、内部人名等），全文扫描，出现即 blocker。

**G. 性能**：图片 width/height 与懒加载；未用字体声明；重复渲染。

## 3. 八类已知失败模式（实战踩坑，逐条必查，最高优先级）

> 这一节是全文最有价值的部分：每一条都是真实事故的抽象。

- **H1 CSS 静默未生效**：HTML 里每个关键 class（panel/stage/card/grid 容器）
  必须在 CSS 里有对应规则；大改后用 `getComputedStyle` 验证设计意图真的落地
  （边框/背景/布局），而不是"类名存在即通过"。
  事故形态：面板基础样式整段丢失 + 父级残留 `text-align:center` → 页面"歪了"，
  而所有 DOM 查询类检查全部通过。
- **H2 真实输入测试**：交互结论必须来自真实输入事件（CDP
  `Input.dispatchMouseEvent` 坐标点击），禁止用 JS `.click()` 下结论——
  它能穿透 `pointer-events:none` 和被遮挡元素，产生"点击成功"假阳性。
  事故形态：标签未闭合导致菜单按钮被吞进隐藏抽屉，JS 点击全部"通过"，
  真机物理不可点。
- **H3 删除声明必须程序化复核**：凡"已删除 X"的改动说明，一律 grep/计数验证
  （尤其多语言 i18n 键 ×N 种语言），不信 changelog；
  各语言键集合做 flatten diff，多键少键都报。
- **H4 选择器漂移**：markup 重命名后，grep 所有媒体查询，找出引用旧类名的
  孤儿规则。事故形态：CTA 容器类改名后，移动端"按钮全宽"规则静默失效。
- **H5 混合对齐**：每个容器只允许一种对齐方式；eyebrow/标题/正文/CTA
  必须共享同一左缘（或同一居中轴）；居中块用 `margin:auto` 实现，
  禁止继承 `text-align` 与限宽块状元素混搭。
- **H6 双视口截图**：结论截图必须同时覆盖桌面宽度与真实手机逻辑分辨率
  （如 402×874），重点拍 CTA 带与栅格区——DOM 断言看不见的不对称，截图能看见。
- **H7 结构增删的连锁反应**：删/增 section 后检查锚点死链、导航项、
  章节编号连续性、回归脚本计数预期是否同步。过时预期是测试问题，
  与代码问题分开报告。
- **H8 信息泄露面**：本地开发服务器路由白名单（docs/、agent 配置、
  凭据文件必须 404）；页面文案过保密词表。

## 4. 技术实现要点

- **无头 Chrome + CDP**：`--headless=new` + `--remote-debugging-port`，
  WebSocket 直连，脚本化设置设备度量（`Emulation.setDeviceMetricsOverride`）、
  导航、求值、截图（`Page.captureScreenshot`，支持 `captureBeyondViewport` 全页）。
- **真实输入**：`Input.dispatchMouseEvent` 按坐标点击，先 `elementFromPoint`
  确认命中目标再派发。
- **几何断言**：`getBoundingClientRect` 比较共享左缘（差 < 2px）、
  居中（中点与视口中点差 < 2px）；`getComputedStyle` 验证边框/对齐意图。
- **i18n parity**：Node 侧源码直接提取各语言字典、flatten 成键路径集合，
  与基准语言 diff。
- **回归即资产**：每修完一个 bug，往验证脚本加一条永久断言；
  断言数随事故数单调增长，同类问题永不复发。
- **白名单静态服务器**：几十行 node:http 即可，路由表只放
  index/src/assets，其余 404——评审用的临时服务器绝不能当文件服务器。

## 5. 输出格式

固定格式：结论（APPROVE / NEEDS-CHANGES + blocker 数）→ 分级发现表
（blocker/major/minor/nit，含位置/证据/建议）→ 客户模拟摘要 → 复核建议。
按严重度降序；同一根因合并为一条；不改代码，只给建议。

## 6. 什么时候跑

- 大结构手术后（导航合并、区块增删、类名重命名）
- 视觉调性改动后（双视口截图必须）
- 对外交付前（F 保密红线 + 服务器泄露面必须）
- 修复后回归靠断言脚本，不靠人肉复看
