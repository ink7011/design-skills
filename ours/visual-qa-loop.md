# 视觉 QA 回路：看图才算完成

> 沉淀自真实实践的通用工艺，与任何具体项目无关。

## 核心原则

**永远不要只看代码/参数就说"做完了"。** 渲染结果与意图之间的偏差只能通过看图发现。
文字没换行、渐变没生效、方角戳出圆角、图片加载失败——这些在源码里全都"看起来正确"。

## 回路（每轮迭代必须走完）

1. **导出**：把产物渲染成位图（SVG→PNG 用无头浏览器，deviceScaleFactor 2，透明底）
2. **上传取得可访问 URL**（供视觉模型检查）
3. **视觉模型逐项验收**：给出**具体的问题清单**，不是开放性问题
4. **逐条对照通过**才允许宣称完成；任何一条不过 → 修 → 重走回路

## 验收问题清单的写法

- ❌ "这个设计好看吗？"（开放问题 → 得到无信息量的回答）
- ✅ "左 1/3 的渐变块圆角是否与外框一致，有没有方角突出？"（可判定的封闭问题）

一次验收 5-8 个封闭问题：形状/对齐/对比度/渲染完整性/元素关系。

## 已知坑档案

| 坑 | 症状 | 解法 |
|---|---|---|
| 图床同名缓存 | 重新上传同名文件，检查看到的还是旧图 | 换全新文件名再上传 |
| 验证命令假阳性 | 命令退出码 0 但实际没效果（如 `ls-remote` 匹配不到 ref 也返回 0） | 验证必须检查**内容**而非退出码；用 API/回读复核 |
| 截图通道超时 | 高页截图偶发超时，重试同样失败 | 等待后重试一次；仍失败换渲染通道（如无头浏览器） |
| 深色模式串色 | 系统深色模式下文档底色被反转 | `<meta name="color-scheme" content="light">` + 显式背景色 + `emulateMedia` 实测 |

## 一条元原则

**"报告完成"的时刻 = 眼睛看到证据的时刻。** 这条对人和对 AI 都成立——AI 最常见的
失败模式就是从源码推断渲染结果并直接宣称成功。
