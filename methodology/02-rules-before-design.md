# 02 · 规则先行：设计之前先定规则和决策

先改规则，再改图。图是规则的执行结果。这一步写出来的文档后面会变成 guideline 的骨架。

## 必须先回答的规则（按顺序）

1. **认证含义**：徽章认证的是什么？写三句限定 + 五句"不暗示"。
   - 限定例：伙伴已被品牌方接受进入网络；具备参与 X 业务的资格；等级/权限/有效期以官方记录为准。
   - 不暗示例：不为伙伴所有产品背书；不担保项目结果；不是永久认证；不含未公开独家权利。
2. **免责声明**：一句话免责（参考 Microsoft footnote 句式），随下载页展示。
3. **认证 ≠ 授权**：身份认证不是分销/商业授权——分开写，法务要过目。
4. **使用资格**：谁能用 + **谁不能用**（"非认证情形"清单：POC 合作、采购过产品、
   被案例报道、参过会、雇佣过前员工……都不等于认证）。
5. **生命周期**：有效 / 复审中 / 降级 / 撤销四种状态下徽章分别怎么处理；
   状态与下载权限绑定；撤销后已发布物料的移除期限。
6. **命名决策**：tier 叫什么、和"认证状态"词会不会撞（"Certified" 既可以是档位名
   也可以是状态名——要么换词，要么在 guideline 里写清修饰关系）。
7. **不进徽章的信息**：年份、区域、名额、商业承诺、能力线、产品 powered 声明
   ——全部放 Portal/验证系统，不放图形。

## 下载与分发（竞品一致的做法）

- 素材下载必须登录（Portal 内），公开页只放预览 + 规则。
- 公开页同时承担"验证入口"职责：看规则 + 查伙伴目录。
